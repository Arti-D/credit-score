# credit-score

## Цель проекта
Учебный проект по кредитному скорингу на данных
[Home Credit Default Risk](https://www.kaggle.com/competitions/home-credit-default-risk).
Цель — научиться оценивать вероятность проблем с платежами и обосновывать выбор порога одобрения заявок. В отчёте проблемной считается заявка с `TARGET = 1` по разметке Home Credit.

## Отчёт для риск-менеджера

**Для учебного сценария выбран LightGBM с порогом 12,2%.** Заявка одобряется, если прогноз вероятности проблем с платежами не превышает 12,2%. Среди порогов с шагом 0,1 процентного пункта этот порог даёт максимум одобрений на выборке подбора при верхней границе 95%-го интервала Уилсона не выше **5%** проблемных заявок среди одобренных. Лимит 5% принят для демонстрации, поскольку в ТЗ отсутствуют стоимость ошибок и бизнес-лимит риска. На выборке подбора доля одобрений составила 80,72%, доля проблемных среди одобренных — 4,73%, верхняя граница интервала — 4,997%.

На независимом тесте с зафиксированным порогом:

| Показатель | Результат |
|---|---:|
| Одобрено заявок | **49 973 из 61 503 (81,25%)** |
| Ожидаемая доля проблемных среди одобренных, средний прогноз | **4,71%** |
| Наблюдаемая доля проблемных среди одобренных | **4,62%** (95% ДИ 4,44–4,81%) |
| Доля проблемных среди всех тестовых заявок | 8,07% |
| Отказов среди заявок с `TARGET = 0` | 8 876 |

LightGBM выбрана по ROC-AUC на выборке подбора. Результаты на тесте:

| Модель | ROC-AUC | Gini | Brier score | Log loss |
|---|---:|---:|---:|---:|
| Логистическая регрессия с WoE | 0,7597 | 0,5195 | 0,06797 | 0,24614 |
| LightGBM | **0,7782** | **0,5564** | **0,06652** | **0,24003** |

**Калибровка.** Для каждой модели сравнили исходные вероятности с сигмоидальной калибровкой. Для обеих моделей оставили исходные вероятности по log loss на выборке подбора. Для LightGBM значения практически совпали — 0,24163653 и 0,24163677 соответственно. График показывает оба варианта на тесте.

**Стабильность.** PSI распределения прогноза между случайными validation и test составил **0,00048**. Для 43 признаков максимальный PSI — 0,00099. В CSV текущих заявок отсутствует календарная дата. День недели, час и дни относительно заявки не позволяют восстановить порядок заявок во времени. Проверка на будущем периоде остаётся открытым пунктом ТЗ. Для неё нужна календарная дата заявки и размеченная выборка более позднего периода. [Описание данных Home Credit на Kaggle](https://www.kaggle.com/c/home-credit-default-risk/data)

**Интерпретация.** На 2 000 тестовых заявок самые высокие средние абсолютные вклады TreeSHAP у `EXT_SOURCE_2`, `EXT_SOURCE_3` и `EXT_SOURCE_1`. Из признаков кредитной истории выделяется `past_late_payment_rate`, доля просроченных среди наблюдаемых исторических платежей. Второй график показывает, какие признаки повышают и понижают логарифм шансов для одной заявки около порога. [Графики TreeSHAP](reports/shap.png)

## Признаки и проверка моделей

DuckDB собирает одну строку на заявку из `application_train.csv`, `bureau.csv`, `previous_application.csv` и `installments_payments.csv`. Историю агрегируем по `SK_ID_CURR` до `LEFT JOIN`. Для кредитов бюро и предыдущих решений используются записи до текущей заявки. Для платежей и плановая дата, и дата наблюдаемой оплаты должны предшествовать заявке. Счётчики для заявок без подходящей истории равны нулю. Остальные агрегаты для таких заявок остаются пропусками. Код витрины находится в [`scoring/features.sql`](scoring/features.sql).

Используем существующее стратифицированное разбиение из `application_train.csv` с `random_state=42`. Скрипт проверяет соответствие заявок один к одному и создаёт `data/processed/application_split.csv`, если файл отсутствует. В Kaggle-файле `application_test.csv` целевая переменная отсутствует.

| Выборка | Заявок | Назначение |
|---|---:|---|
| Train | 184 506 | Обучение обеих моделей, биннинг и оценка WoE |
| Validation для калибровки | 30 751 | Обучение сигмоидальной калибровки |
| Validation для подбора | 30 751 | Сравнение моделей и калибровок, выбор порога |
| Test | 61 503 | Итоговая оценка выбранного решения |

Для WoE числовые признаки разбиваются по квантилям train, а признаки с десятью и менее значениями — по наблюдаемым значениям. Редкие категории объединяются, пропуски получают собственную группу. Используется `WoE = ln(доля группы среди TARGET = 1 / доля группы среди TARGET = 0)` со сглаживанием 0,5. LightGBM получает исходные значения той же витрины. Для PSI сравниваются доли по одним и тем же группам в обеих выборках.

## Запуск проекта

Результаты получены с Python 3.14. Помести четыре CSV для обучения в `data/raw`. Для ноутбука `01` туда же нужен `HomeCredit_columns_description.csv`. Из корня репозитория в активированном виртуальном окружении выполни:

```shell
python -m pip install -r requirements.txt
python -m scoring.train
python -m scoring.report
```

Первый запуск обучения сохраняет агрегированные метрики в `data/processed/scoring_results.json`. Команда `scoring.report` обновляет графики и `reports/index.html`. HTML можно открыть локально в браузере. Для EDA выполни ноутбуки `01` и `02`, для разбора сплита и первого эксперимента — `03` и `04`. Исходные CSV, производные данные с записями по заявкам и виртуальное окружение исключены из Git.
