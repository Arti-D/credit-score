# credit-score

## Цель проекта
Учебный проект по кредитному скорингу на данных
[Home Credit Default Risk](https://www.kaggle.com/competitions/home-credit-default-risk).
Цель — научиться оценивать вероятность проблем с платежами и обосновывать выбор порога одобрения заявок.

## Что уже сделано
- Проверены идентификаторы заявок, распределение целевой переменной и пропуски.
- Исследованы распределения дохода, суммы кредита, возраста и стажа на текущем месте работы.
- Обнаружено и отдельно рассмотрено специальное значение `365243` в `DAYS_EMPLOYED`.
- Создано воспроизводимое стратифицированное разбиение на train / validation / test в пропорции 60 / 20 / 20. Проверены отсутствие пересечений и полнота состава заявок.

## Проверка будущих моделей

Разбиение строится из `application_train.csv`, где известен `TARGET`.
Используются стратификация по `TARGET` и `random_state=42`.
Соответствие `SK_ID_CURR` и части выборки сохраняется в `data/processed/application_split.csv`.

Разбиение случайное, а не временное: оно не оценивает перенос модели на будущий период.
Train предназначен для обучения, validation — для выбора моделей и настроек,
test — для итоговой оценки. В `application_test.csv` целевая переменная отсутствует.

## Запуск проекта
1. Клонировать репозиторий.
2. Положить исходные данные ([Kaggle](https://www.kaggle.com/competitions/home-credit-default-risk)) в созданную в корне репозитория папку data/raw
3. Установить зависимости: `python -m pip install -r requirements.txt`.
4. Создать папку `data/processed` для результатов.
5. Открыть нужный ноутбук в редакторе с поддержкой Jupyter и выполнить ячейки сверху вниз. Рекомендуемый порядок — `01`, `02`, `03`.

Исходные CSV, производные данные и виртуальное окружение не включены в репозиторий.

## Дальнейший план

- Учебный запуск логистической регрессии на нескольких признаках.
- Сборка признаков из нескольких таблиц через SQL и DuckDB.
- Логистическая регрессия с WoE-биннингом и сравнение с LightGBM.
- ROC-AUC и Gini, калибровка вероятностей, PSI и исследование возможности временной проверки.
- Интерпретация через SHAP и краткий отчёт с обоснованием cut-off и оценкой доли проблемных заявок среди одобренных.
